The aikit Pipeline

One task, from request to merge, with nobody watching. Two gates stand in its way, and neither can be talked around — the reviewer has no tool that edits, and the acceptance agent is never shown the code.

    Why the gates hold

    no Write

    The reviewer cannot patch what it finds. Its tool list has no Write and no Edit at all, so independence is enforced by the harness — not by an instruction it could talk itself out of on a long run.

    no diff

    The acceptance agent never sees the code. Its brief is four things and contains no file name. An agent holding the diff inherits the author's blindness and checks what the code says instead of what a person needs.

    exit 1

    The gate is a program, not a paragraph. An incomplete report — no “what I could not check” line, a passed item with no evidence — blocks exactly like a breakage does.

    Where it stops instead of guessing

    Unattended is not the same as unsupervised. Each of these ends the run, keeps every fix made so far, and hands the owner a report with the exact next action — rather than picking an interpretation and building on it.

    round cap spent

    Three review rounds, or three acceptance rounds, with blocking issues still open.

    ping-pong

    A reviewer reversing an earlier round's finding. Both positions go to the owner; no side is picked by editing.

    stand won't come up

    Or a budget runs out mid-acceptance. That is “could not”, never “good”.

    the scope grew

    Work the plan doesn't mention is a new milestone to approve, not a bigger one to finish.

    the plan is wrong

    The milestone can't be built as written, or means something else. Say so; don't build your own reading of it.

    anything irreversible

    Production, deleted data, a force-push, a rotated credential — unless the plan named it.
